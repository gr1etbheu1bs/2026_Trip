# ACTIVE Task

Status: READY

## Goal

2026年軽井沢旅行を既存旅行とは完全に別管理にし、実績・固定予定・候補をGitHub Pages上で確認し、**軽井沢プリンスホテル ウエストを拠点とした計画用の移動時間目安**を見ながら候補を選べる最小の旅行Top pageを作る。

このtaskは **軽井沢旅行の独立Top page＋初期データ＋候補選択/移動時間UIを成立させる** 1 goalだけ。

## Required context

最初に次だけを読むこと。

- `README.md`
- `AGENTS.md`
- `docs/tasks/ACTIVE.md`
- `docs/index.html`

既存 `docs/data/*.csv` は別旅行のdataなので変更しない。ただし既存設計の考え方として「地点間の計画用所要時間をstructured dataで持つ」ことは踏襲する。

必要な場合のみ `docs/index.html` が実際に参照するassetを確認する。repo全体scanやWeb調査はしない。

## Scope

1. `docs/trips/karuizawa/` を軽井沢旅行専用namespaceとして新設する。
2. `docs/trips/karuizawa/index.html` をGitHub Pagesで利用できる軽井沢旅行専用Top pageとして作る。
3. `docs/trips/karuizawa/data/` に、この旅行だけのstructured dataを置く。
4. Top pageでは次を明確に区別する。
   - 訪問済み・実績
   - 固定予定・制約
   - 検討中候補
   - 候補選択/移動時間の計画UI
5. 今回の旅行の**固定拠点は `軽井沢プリンスホテル ウエスト`** とする。ホテル名は公開情報としてrepository / UIへ明示してよい。住所、予約番号、部屋番号等の不要な宿泊詳細は持たない。
6. 旅行期間は `2026-08-16`〜`2026-08-23`。

## Planning travel-time data

1. 既存旅行と同様に、**計画用の目安所要時間をstructured dataとして持つ**。
2. realtime値ではなく、通常時の旅程組み立て用の概算値であることをUIに明記する。
3. 基本表示は固定拠点 `軽井沢プリンスホテル ウエスト` から各candidateへの車移動目安とする。
4. 初期値は次を使う。過度な精度を示さず `約` 表示にする。

| From | To | planning_minutes | note |
|---|---|---:|---|
| 軽井沢プリンスホテル ウエスト | 軽井沢ゴルフ練習場・パターコース | 5 | 通常時の計画目安 |
| 軽井沢プリンスホテル ウエスト | 軽井沢風越公園 / 軽井沢アイスパーク | 15 | 約4km。通常時の計画目安 |
| 軽井沢プリンスホテル ウエスト | 竹内ゴルフ練習場 | 40 | 北軽井沢方面。通常時の計画目安 |
| 軽井沢プリンスホテル ウエスト | 軽井沢おもちゃ王国 | 50 | 北軽井沢・嬬恋方面。通常時の計画目安 |

5. **竹内ゴルフ練習場と軽井沢おもちゃ王国は同方面**と分かるようにし、候補選択時にセットで検討しやすくする。
6. candidateを選んだ時、少なくとも「ホテルから約○分」を表示できるようにする。
7. 将来candidate間の所要時間を追加できるよう、travel-time dataは `from` / `to` / `minutes` を持つ拡張可能な形にする。ただし今回不要な全組合せは作らない。
8. Google Mapsへの導線も残す。repositoryの目安値は日程計画用、Google Mapsは出発直前の渋滞等を含む確認用という役割分担にする。
9. Google Maps API key、backend、リアルタイムAPI取得は追加しない。
